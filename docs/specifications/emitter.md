# Emitter

Status: CONFIRMED
Scope: Normative
Last updated: 2026-11-28

## Purpose

The emitter converts a validated immutable document into deterministic Typst
source. It is a pure function of the document, the product version, and the
emitter configuration. It does not read assets, invoke the compiler, or write
files.

The emitter is implemented in both SDKs. The public API is the method
`Document.to_typst(config=None)` in Python and `Document.toTypst(options?)` in
TypeScript, and the method returns the source as a string. The decision is
recorded in ADR-0028.

## Output contract

| Property | Rule |
|---|---|
| Encoding | UTF-8, no byte order mark. |
| Line endings | LF. |
| Final newline | Exactly one trailing newline. |
| Timestamps | None. |
| Random identifiers | None. |
| Absolute paths | None. |
| Header | A fixed generated-file comment. |
| Determinism | The same input produces identical bytes. |

The header is:

```typst
// Generated by Typcast. Do not edit.
```

The header does not include the product version. Including the version would make
golden files change on every release without a semantic output change.

## Emission order

1. Generated-file header.
2. Module imports, in declaration order.
3. Page setup.
4. Document metadata.
5. Blocks, in document order.

A blank line separates top-level sections. Blocks are separated by one blank
line. The output ends with one newline.

## Page setup

Portrait:

```typst
#set page(
  paper: "a4",
  flipped: false,
  margin: (top: 2cm, right: 2cm, bottom: 2cm, left: 2cm),
)
```

Landscape:

```typst
#set page(
  paper: "a4",
  flipped: true,
  margin: (top: 2cm, right: 2cm, bottom: 2cm, left: 2cm),
)
```

Rules:

- `paper` is emitted as a quoted string from the catalog.
- `orientation: "portrait"` emits `flipped: false`.
- `orientation: "landscape"` emits `flipped: true`.
- Margins are emitted in the order top, right, bottom, left.
- Lengths are emitted as a number followed by the unit, with no space.
- Integers are emitted without a decimal point.
- Non-integers use a decimal point and the shortest round-trippable form.

## Document metadata

```typst
#set document(
  title: "Quarterly Report",
  author: "Example Corp",
  date: datetime(year: 2026, month: 11, day: 24),
)
```

Rules:

- `title` is always emitted.
- `author` is emitted only when present.
- `date` is emitted only when present.
- Strings escape backslashes and double quotes.
- Date strings are parsed as `YYYY-MM-DD` and emitted as `datetime(...)`.
- Metadata is emitted after page setup and before content.

## Module imports

Alias import:

```typst
#import "modules/report.typ" as report
```

Item import:

```typst
#import "modules/format.typ": currency, percent
```

Rules:

- Imports appear before page setup.
- Import order follows the document's module order.
- Paths use `/` separators.
- Paths are quoted and escaped.
- Alias and item imports are mutually exclusive.
- No remote or package imports are emitted by the MVP.

## Blocks

### Heading

```typst
= Heading level 1
== Heading level 2
```

- Emit `=` repeated by level, one space, then inline content.
- Do not add automatic numbering.
- Do not add labels.

### Paragraph

```typst
Revenue grew by *12%*.
```

- Emit inline content on one logical paragraph.
- A paragraph ends with a blank line.
- Do not add indentation.

### List

```typst
- First item
- Second item
```

```typst
+ First item
+ Second item
```

- Bullet lists use `-`.
- Ordered lists use `+`.
- Each item is emitted on its own line.
- Items are separated by a newline, not a blank line.
- A blank line follows the list.

### Table

```typst
#table(
  columns: 2,
  align: (left, right),
  table.header([Metric], [Value]),
  [Revenue], [1,200],
  [Cost], [800],
)
```

- `columns` is the column count.
- `align` is a tuple of column alignments.
- Header cells are emitted with `table.header`.
- Data cells are emitted row by row.
- Cell content is inline content.
- Empty cells emit `[]`.
- The table is a block; a blank line follows it.

### Image

```typst
#figure(
  image("figures/revenue.png", alt: "Revenue chart", width: 12cm),
  caption: [Figure 1],
)
```

- Emit `#figure(image(...), caption: [...])`.
- `alt` is always emitted.
- `width` is emitted only when present.
- `caption` is emitted only when present.
- The path is quoted and uses `/` separators.
- If the supported compiler does not accept `alt`, the adapter reports a
  compatibility error; the emitter does not silently drop it.

### Page break

```typst
#pagebreak()
```

- Emit on its own line.
- A blank line follows the block.

### Raw block

```typst
#figure(image("logo.png"), caption: [Logo])
```

- Emit the raw value verbatim.
- Do not escape, indent, or wrap it.
- A blank line precedes and follows the block, except at the start or end of the
  document.

## Inline spans

| Span | Emission |
|---|---|
| `text` | Escaped text. |
| `bold` | `*` + inline content + `*`. |
| `italic` | `_` + inline content + `_`. |
| `monospace` | Backtick + raw text + backtick. |
| `link` | `#link("href")[` + inline content + `]`. |
| `lineBreak` | `#linebreak()`. |
| `raw` | Verbatim value. |

Nested emphasis is emitted recursively. Adjacent spans are emitted in order with
no inserted separators.

### Monospace

A monospace span is emitted as the raw text of Typst:

```typst
`report --format json`
```

The raw text of Typst holds no escape sequence, so the rules below apply:

- The content of a monospace span is emitted verbatim. The escaping table of
  the node catalog does not apply inside the raw text, because a backslash in
  the raw text is a literal backslash.
- A monospace span holds text spans and raw spans only. A span of another type
  cannot be represented in the raw text, and the emitter rejects it with
  `TYPCAST-EMIT-0003`.
- The content of a monospace span holds no backtick, because a backtick would
  end the raw text. The emitter rejects such a value with
  `TYPCAST-EMIT-0003`.
- The emitter returns no partial output when it rejects a value.

## Escaping

Text escaping follows `nodes.md`. In addition:

- Module and image paths escape backslashes and double quotes.
- Link URLs escape backslashes and double quotes.
- Metadata strings escape backslashes and double quotes.
- Raw content is never escaped.
- The emitter does not HTML-escape content.
- The emitter does not normalize Unicode.

### List markers

Typst reads a hyphen or a plus at the start of a line as the marker of a list.
The emitter therefore escapes a list marker when the text starts a line and the
marker is followed by a space or ends the value:

| Text | Emission |
|---|---|
| `- A bullet` | `\- A bullet` |
| `+ A number` | `\+ A number` |
| `-dash` | `-dash` |
| `A - bullet` | `A - bullet` |

The rule is context-sensitive. The emitter applies it to the first span of a
paragraph, of a table cell, of an image caption, and of the content of a link.
A heading starts with the markers of its level, so a heading is not a list and
its text is not escaped.

## Error handling

The emitter:

- MUST validate the document before emission.
- MUST reject unknown block or span types with `TYPCAST-EMIT-0002`.
- MUST reject an internal invariant failure with `TYPCAST-EMIT-0001`.
- MUST reject a value that cannot be escaped safely with `TYPCAST-EMIT-0003`.
- MUST NOT return partial output when an error occurs.
- MUST NOT invoke the compiler.
- MUST NOT read or write assets.

The validation of the document raises `ValidationError` with every error
diagnostic of the semantic engine. The failures of the emitter itself raise
`EmitError` with one diagnostic of the family `TYPCAST-EMIT-*` and the phase
`emit`.

## Golden files

Every emitter change must be covered by at least one golden fixture. A golden
fixture consists of:

```text
tests/fixtures/documents/<name>.json
tests/fixtures/expected/<name>.typ
```

The test compares the emitter output to the expected file byte for byte. Golden
files are updated only by an explicit review that explains the output change.

The golden files are shared by both SDKs. Every valid document of the manifest
under `tests/fixtures/documents/` has one golden file, and the runners
`//tests/contract:typst_py` and `//tests/contract:typst_ts_test` compare
their output with that file, so a drift in either SDK fails one of the two
contract targets.

## Open questions

- Should the generated-file header include the schema version?
- Should tables always be wrapped in a figure when a caption is added later?
- Should the emitter support a compact output mode for debugging?
